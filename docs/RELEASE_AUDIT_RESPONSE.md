# Response to the release follow-up audit

Response to [PAPERAID_V2_RELEASE_AUDIT.md](PAPERAID_V2_RELEASE_AUDIT.md) (snapshot `691c6c0`, 14 November 2026).
All 12 findings are fixed, each with regression tests. Most are in `backend/tests/test_release_audit.py` (24 tests);
the frontend tests are in `frontend/src/test/guidance.test.tsx` and `writing.test.tsx`. Schema change: migration
`e5f3a8c1d927` (expand-only).

| # | Severity | Finding | Fix | Tests |
|---|---|---|---|---|
| 1 | High | Account ZIP bypasses current paper visibility | Every paper-derived ZIP entry (library, notes, CSL-JSON, BibTeX, collections, document citation records) applies the same `visible_papers_clause` as the library routes. Uploads are selected by `owner_id`. | Seeded stale library link and citation to another person's private paper: nothing appears in any ZIP file, including file names. |
| 2 | High | Stale worker can leave a live PDF eligible for deletion | Each PDF write gets its own key (`papers/<id>/<sha>-<nonce>.pdf`), so attempts never share an object. Maintenance also refuses to delete any object a paper still points to (indexed `storage_path`). The initial `PROCESSING` update in `run_job` is fenced by the attempt token. | The audit's scenario: attempt B publishes, stale attempt A writes the same bytes and loses the lease. Maintenance deletes only A's object, and B's PDF stays readable. A live-object intent is skipped. Identical bytes get distinct keys. |
| 3 | High | Concurrent releases can promote an unchecked revision | `release.sh` takes a per-service lock (Cloud Storage object created only if absent). It deploys by image **digest** under a **unique** tag and reads the revision and URL from the **same** traffic entry. `/ready` reports `K_REVISION`, and the gate requires it to equal the revision being promoted. Carriage returns from Windows Python are stripped. | Runs the real script against a fake `gcloud`/`curl`/`git`: an interleaved second release does not get promoted, a probe that reaches a different revision stops the release before any traffic change, and a held lock stops the release before the build. |
| 4 | Medium | Interrupted account closure needs manual recovery | `closed_accounts` is now a durable closure request (user id, options, attempts, last error, back-off, completion). If a step fails, the person is told the account is closed and the deletion will finish automatically (HTTP 202). Maintenance resumes open requests with a lease and exponential back-off. | Identity provider outage → 202 → account locked → maintenance completes it. Failure after identity deletion → resumed. Repeated failure backs off and is not retried early. |
| 5 | Medium | Export incomplete; unavailable during re-consent | The ZIP now adds collections and their membership, each document's version history and citation records (the IDs its content refers to), every owned PDF even if it is no longer in the library, stable IDs, and `manifest.json` (all files, plus any that could not be read). Download and delete use a data-rights principal that works before re-consent and for former testers. The consent screen and the "not on the tester list" screen offer both actions. | Removed-from-library upload, collection, citation, history and manifest are all present. Export and delete work before re-consent and after removal from the tester list. UI test of the consent screen. |
| 6 | Medium | Consent stamped with a version the browser did not show | The consent form sends the version it displayed, and the API records acceptance only for that exact version. An outdated or missing version gets `409 POLICY_OUTDATED` with the current version, and the page offers a reload. | Old version and missing version are both refused and nothing is recorded. The current version is accepted. The UI sends `policy_version`. |
| 7 | Medium | Optional consent can diverge from its audit record | The `consent_*` keys are reserved: the generic preferences route rejects them. Both routes update only their own keys with an atomic JSONB merge (never read-modify-write of the whole object), and consent decisions are written in the same transaction as their audit record. | The generic route cannot set or remove a consent. Concurrent preference and consent saves keep both changes, and the stored value equals the last audit record. |
| 8 | Medium | Public routes expose private work before re-consent | `get_optional_user` treats an account that has not accepted the current notices as anonymous. | Before re-consent: own private paper details and passages return 404, and the catalog leaves the paper out. |
| 9 | Medium | Highlights can omit support or hit the wrong characters | All supporting quotes are kept (no cap of three). Offsets are sent in UTF-16 code units (`offset_unit: "utf16"`), the unit of browser string slicing. | Four quotes on one source → four highlights. Emoji before a quote → exact browser slice (Python and UI tests). An unaligned source is dropped. The verifier prompt contains the excerpt, not the full passage. |
| 10 | Medium | Private uploads can duplicate or get stuck | Concurrent uploads of the same file by the same person are serialized by a transaction-scoped advisory lock with a re-check, so exactly one paper is created and the losers' objects are queued for deletion. Transport errors while queueing become a known error, so the upload stands and the paper shows why. Private papers with a stored PDF get **Retry text extraction**. Re-uploading the same file retries a failed extraction. | Three concurrent identical uploads → one paper, live object kept. Queue transport failure → upload kept with a retry message, then re-upload recovers. Owner retry of a private upload. UI retry button. |
| 11 | Medium | Staging recipe reuses production credentials | `DEPLOYMENT.md` now defines staging as a separate project with its own Firebase project, database principal, bucket, queue and service accounts. Nothing was provisioned. | Documentation (no resources created). |
| 12 | Medium | Repeated citations show the wrong label in the editor | Labels are applied **by occurrence**: the n-th citation node gets the n-th rendered entry (the server and ProseMirror use the same depth-first order). A render whose citation sequence no longer matches the editor is ignored as stale. | Repeated citation in a note style keeps "full first note, short later note". A stale render is ignored. |

## Notes on the auditor's recommendations

- **Inline AI and sharing held back.** AI is still not configured in production, so ghost suggestions, AI
  rewrite and "check against my sources" do not appear. They appear only once a provider key is added. Sharing
  has not been built.
- **Beta stays invite-only.** Nothing in this change widens access.
- **Large exports.** The ZIP is still built in a spooled temporary file (memory up to 64 MB, then disk) before it
  streams. That is adequate for the test cohort. A background export job is the next step if archives grow large.
- **Signed-in end-to-end check in isolated staging.** This waits on the staging project (a maintainer decision,
  see `DEPLOYMENT.md`).
