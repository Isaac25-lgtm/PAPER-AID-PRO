## Findings

### SF01. [SEVERITY: high] Optional embeddings send non-pilot researchers’ private text to the provider

- **Where** [processing.py line 392](../backend/app/services/processing.py#L392), [features.py line 39](../backend/app/services/ai/features.py#L39), [search.py line 63](../backend/app/services/search.py#L63), [DEPLOYMENT.md line 171](../docs/DEPLOYMENT.md#L171).
- **What** The chat cohort is enforced on AI routes. The upload worker and passage search select an embedder from global configuration. Neither checks the owner’s pilot eligibility before submitting document chunks or a query.
- **Impact and evidence** Enabling the optional embedding provider alongside an AI key can send a non-pilot user's private PDF text and search terms off-platform. The current default is off. This is an activation blocker, with no evidence of a live disclosure. In a local non-pilot upload test, the status endpoint reported AI off for the account and the fake embedder still received eight private document chunks (2,673 characters) and the subsequent passage query. No content was sent to an outside provider.
- **Recommended fix and regression** Thread eligibility and data-use policy through ingestion, backfill and passage search. Preserve local keyword search for ineligible users. Update the notice to describe indexing if the owner intends to offer it. Test non-pilot private uploads and ordinary searches with a recording fake, eligible users, and the administrative backfill.

### SF02. [SEVERITY: medium] The handover puts a private question and paper selections into browser history

- **Where** [DeepResearch.tsx line 240](../frontend/src/pages/DeepResearch.tsx#L240), [Research.tsx line 132](../frontend/src/pages/Research.tsx#L132), [firebase.json line 33](../firebase.json#L33).
- **What** Both handover directions put the full research question in the URL. Deep-to-Ask includes the selected paper UUIDs. The published referrer policy truncates cross-origin referrers but permits the full same-origin referrer.
- **Impact and evidence** A researcher who copies the address, uses a shared browser or reloads the page can expose a question they entered in a private workspace. Reload sends the path and query to the hosting origin. Paper ownership still prevents another account from reading the records by ID.
- **Recommended fix and regression** Use ephemeral, account-scoped navigation state for unsaved questions. For resumable transfers, use an opaque owner-checked handover ID. Test Back, reload, account switch, and that the address, generated links and same-origin resource referrers contain no research text.

### SF03. [SEVERITY: medium] PDF export interprets ordinary reference text as PDF link markup

- **Where** [export.py line 322](../backend/app/services/export.py#L322), [export.py line 329](../backend/app/services/export.py#L329), [export.py line 360](../backend/app/services/export.py#L360).
- **What** The exporter combines escaped plain text and generated links into one string for fpdf2's Markdown parser. Its plain-text escape omits link syntax and some formatting markers.
- **Impact and evidence** In a one-page local export, a literal appendix reference containing a bracketed label followed by a parenthesized page number made PDF serialization fail with an invalid page reference. A reference containing paired tildes lost its literal markers. Word preserved the text.
- **Recommended fix and regression** Emit literal text and verified HTTP(S) destinations as separate PDF fragments using explicit links, while preserving existing line wrapping, Unicode and style handling. Test ordinary bracketed notation, tildes, query parameters, balanced DOI parentheses and reference text pasted by a user. Inspect the actual PDF annotations and DOCX relationships.

### SF04. [SEVERITY: medium] Open-access Discover misses matching papers beyond the unrestricted first page

- **Where** [discovery.py line 276](../backend/app/api/routes/discovery.py#L276), [aggregator.py line 277](../backend/app/services/scholarly/aggregator.py#L277), [providers.py line 141](../backend/app/services/scholarly/providers.py#L141).
- **What** The one-shot route forwards open_access_only to upstream searches. The stream forces the provider flag to false and filters a short list after retrieval. Most users now enter through the stream.
- **Impact and evidence** A controlled OpenAlex provider returned a closed paper for the unrestricted search and an open paper for its open-only search. The same request produced zero results through the streaming route and one through the one-shot route. The mock saw flags false and true respectively.
- **Recommended fix and regression** Pass the open-access flag through progressive search, retaining the final defensive filter. Derive pending providers from the same available set that actually runs. Test both endpoints against an open paper outside the unrestricted first page, and repeat with warm caches.

### SF05. [SEVERITY: medium] Retry can report a recovered database while withholding its papers

- **Where** [searchStream.ts line 97](../frontend/src/lib/searchStream.ts#L97), [searchStream.ts line 104](../frontend/src/lib/searchStream.ts#L104), [Discover.tsx line 186](../frontend/src/pages/Discover.tsx#L186).
- **What** The hook keeps the previous results until every previously healthy provider succeeds again. A prior success that now fails stays marked successful. The newly recovered provider can also be marked successful while its result list is discarded.
- **Impact and evidence** In a rendered Discover test, provider A succeeded and B failed. On retry B supplied a new paper and A failed. The old paper remained, the recovered paper never appeared, and the Retry button disappeared. This can happen on a new API instance or after cache expiry.
- **Recommended fix and regression** Retain data and freshness per provider. Retry the failed subset explicitly or identify the origin of results so the client/server can merge an old success with a new one. Preserve stale and failed states. Test swapped successes, a new search during retry and duplicate records across providers.

### SF06. [SEVERITY: medium] One accepted search can spend many upstream requests outside the caller's rate limit

- **Where** [spelling.py line 163](../backend/app/services/scholarly/spelling.py#L163), [spelling.py line 169](../backend/app/services/scholarly/spelling.py#L169), [http.py line 78](../backend/app/services/scholarly/http.py#L78), [discovery.py line 296](../backend/app/api/routes/discovery.py#L296).
- **What** Search rate limits count incoming operations. Rechecking three split words is capped, but every aligned word replacement can launch two OpenAlex count requests concurrently. Different users and cold cache misses have no shared provider-specific pacing or identical-request coalescing.
- **Impact and evidence** Legitimate simultaneous searches can exhaust a shared scholarly-service quota or create a burst of 429s even while every caller stays within their PaperAid allowance. The upstream arithmetic and timeout assumptions are below. No live quota was consumed to establish this.
- **Recommended fix and regression** Deduplicate repeated words, cap confirmations per search, and pace all callers sharing each provider credential with a bounded rate/concurrency budget. Respect long Retry-After values without occupying a request and skip optional spelling on exhaustion. Test with a fake clock, two simultaneous users, partial outages and repeated terms.

### SF07. [SEVERITY: medium] Identifier outages are shown as proof that no registry has the paper

- **Where** [aggregator.py line 298](../backend/app/services/scholarly/aggregator.py#L298), [discovery.py line 248](../backend/app/api/routes/discovery.py#L248), [Discover.tsx line 226](../frontend/src/pages/Discover.tsx#L226).
- **What** Identifier resolution collapses provider outages and authoritative misses into the same empty result. The stream returns no provider statuses and the UI says no registry has a record.
- **Impact and evidence** An ordinary lookup during a temporary outage can lead a researcher to reject a valid DOI, with no failed-provider status or retry action. A mixture of genuine misses and unavailable sources is also inconclusive. With all DOI lookups returning controlled upstream errors, the real HTTP endpoint emitted empty results, no provider statuses and a normal done event.
- **Recommended fix and regression** Return attempted/reached/error status alongside the lookup result, preserve successful matches and offer retry for incomplete coverage. Cover all-miss, all-unavailable, partial outage and successful resolution in both search routes and the Discover UI.

### SF08. [SEVERITY: medium] A handover can save a partial set without telling the researcher which papers succeeded

- **Where** [DeepResearch.tsx line 223](../frontend/src/pages/DeepResearch.tsx#L223), [DeepResearch.tsx line 238](../frontend/src/pages/DeepResearch.tsx#L238).
- **What** The mutation commits up to eight library additions one by one. A failure exits before invalidating the library query or navigating. Successful earlier writes remain. The success callback also navigates without checking whether the originating view is still active.
- **Impact and evidence** A rendered Deep Research handover with a successful first save and failed second lookup showed only the lookup error. It gave no saved count or way to continue with the completed set. Starting again retries already completed work. A late completion can also request navigation after the user has moved on.
- **Recommended fix and regression** Record per-source outcomes, invalidate the library after any successful write, and offer continue-with-saved and retry-failed actions. Bind navigation to the originating view/run. Keep existing idempotent membership/upsert behavior. Test partial success, two equivalent identifiers and leaving the view mid-transfer.

### SF09. [SEVERITY: medium] The Hosting release procedure does not verify the environment baked into the frontend

- **Where** [DEPLOYMENT.md line 68](../docs/DEPLOYMENT.md#L68), [api.ts line 45](../frontend/src/lib/api.ts#L45), [firebase.ts line 5](../frontend/src/lib/firebase.ts#L5), [deploy-staging-frontend.sh line 31](../deploy/deploy-staging-frontend.sh#L31).
- **What** The API release verifies bindings on the exact candidate. The production frontend recipe builds from the working environment and publishes the resulting directory. There is no corresponding assertion that the compiled API origin, Firebase project and auth domain match production.
- **Impact and evidence** A production-mode build in an isolated checkout succeeded with synthetic wrong API and Firebase environment values. The emitted JavaScript contained the synthetic settings. A Hosting project flag selects the destination but cannot correct the bundle; CSP can turn this into a user-visible outage. No artifact was deployed.
- **Recommended fix and regression** Add a local, deterministic frontend release preflight. Validate resolved public settings against the target, stamp commit/target in the artifact, check the artifact and CSP agree and test the wrong-environment case. Require the same artifact to pass before publishing. Keep production and staging release approvals separate.

### SF10. [SEVERITY: medium] A stream ending without its final event leaves Discover searching indefinitely

- **Where** [api.ts line 157](../frontend/src/lib/api.ts#L157), [api.ts line 176](../frontend/src/lib/api.ts#L176), [searchStream.ts line 116](../frontend/src/lib/searchStream.ts#L116).
- **What** The reader resolves on end of body or absent reader. The hook only finalizes on a done event or rejection. It does nothing on successful transport completion without that event.
- **Impact and evidence** A component test delivered a query event then closed the stream normally. A provider stayed marked searching and no retry action appeared. A transport that explicitly throws follows a different error path.
- **Recommended fix and regression** Track protocol completion and active attempt identity. If a live attempt reaches EOF before done, preserve received papers, turn pending providers into retryable failures and surface a concise status. Test empty body, EOF after one result, intentional abort and late events from an older attempt.

### SF11. [SEVERITY: low] A newly inserted citation can be described as unavailable

- **Where** [CitationPopover.tsx line 31](../frontend/src/components/editor/CitationPopover.tsx#L31), [CitePalette.tsx line 156](../frontend/src/components/editor/CitePalette.tsx#L156), [Editor.tsx line 127](../frontend/src/pages/Editor.tsx#L127).
- **What** The popover trusts a citation list cached for 30 seconds. The insert paths post the new citation and flush the editor without updating that list. Failed individual paper queries also have no explicit error state.
- **Impact and evidence** A rendered popover given a fresh pre-insert cache displayed 'source is no longer available' for a citation that the API fixture could return. First-open browser checks do not exercise this ordering.
- **Recommended fix and regression** Merge returned citations into the document-specific cache or invalidate it after all insertion paths, including PDF quotes. On a missing ID, perform one bounded refresh and distinguish an unavailable paper from a failed request. Test two sequential insert-and-open operations and a mixed multi-source citation.

### SF13. [SEVERITY: low] A citation chip cannot open its source through the keyboard command path

## Stream lifecycle, resource limits and cache integrity

**Disconnect.** I opened the real streaming route generator through a local Uvicorn HTTP socket, waited until one provider had answered, then closed the client while another provider and spelling were pending. Both pending operations observed cancellation. The short enrichment session entered and exited once. A separate generator-close check showed the nested provider task could finish cleanup on a later event-loop turn. The normal disconnect path worked in these checks. The finally blocks signal cancellation without joining the tasks. Make ownership explicit with structured cleanup or cancel-and-await where practical. The one-shot route also creates a spelling task before awaiting the main search and lacks an encompassing finally if that await is interrupted. None of these checks demonstrates a sustained production leak. [Stream route](../backend/app/api/routes/discovery.py#L252) · [Progressive producer](../backend/app/services/scholarly/aggregator.py#L273)

**Connection demand.** Each results event opens a short-lived session to map public DOI/PMID matches. If there are no such identifiers the session need not check out a database connection. An ordinary five-provider search can do five enrichment round trips, sequentially per client; a corrected search falling back to the typed query can do ten. There is an additional admission path: the rate limiter commits once for a signed-in caller and normally twice for an anonymous caller. Subsequent results can look up the same top-ranked records repeatedly. The pool sizes recorded in the deployment guide allow up to 20 API connections across four instances against about 25 database connections, before jobs and other consumers. That is a capacity estimate, not a load-test result. Keep one short session per event for now, resolve only newly encountered IDs, and measure SQL pool wait, statement count and first-result latency at realistic concurrent search volumes before increasing the pool. [Result enrichment](../backend/app/api/routes/discovery.py#L68) · [Limiter](../backend/app/security/rate_limit.py#L29) · [Deployment envelope](DEPLOYMENT.md)

**Calls per uncached keyword submission.** These bounds describe the search and spelling code paths, not a benchmark or exact bill. Deadlines, caches, fewer replacements or empty results normally reduce them.

| Provider or phase | Logical requests and retry envelope |
| --- | --- |
| NCBI spelling | One whole-query ESpell request and up to three individual rechecks. The individual checks can run concurrently. ESpell uses a direct HTTP GET and four-second call timeout. |
| PubMed search | Up to one ESearch and one batched EFetch per pass when IDs are returned. Two passes can cost four logical calls, up to 12 HTTP attempts including the shared transport's two retries. Including spelling, the combined NCBI envelope is up to 16 attempted requests. A single user search can exceed the brief's unkeyed three-per-second allowance during bursts. |
| OpenAlex | Up to two count requests per changed word, with retries disabled for counts. A 300-character question can contain up to 75 eligible three-letter words. Thus 150 count calls is a conservative structural ceiling, not an observed typical count. Two provider searches can add two logical requests or up to six HTTP attempts. The three single-word cap does not cap all aligned replacements. |
| Other providers | Each selected available provider is scheduled once per pass. A corrected pass yielding no visible works may trigger a second pass. Identifier resolution has its own multi-registry fan-out and can enrich a PMID/arXiv result by its DOI. Retrying on another instance or after TTL expiry repeats successful work. |
| Slow Europe PMC | Its timeout is 12 seconds per provider pass. Faster databases can already display results. The UI waits for done to expose terminal controls; a corrected-empty fallback can incur a second slow pass, plus the initial spelling decision. Retain partial results and indicate slow providers. Make retry possible when failures are known and give each request an explicit final state. |

**Cache keys and visibility.** Provider, folded query, bounded upstream limit, year limits, open-access flag and subject are represented in the provider cache key. The stream supplies the wrong open-access value (SF04). Only public registry metadata goes into this cache. Local paper lookup explicitly filters to public visibility. The field named library_paper_id therefore points to a public catalog match and does not establish personal library membership. The private paper selection used for Ask goes through the authenticated server. Explicitly requesting an unavailable optional provider can still leave it in the stream's pending list because the route announces its initial selection and the producer removes unavailable providers. Report that state as skipped and derive both lists together. [Registry cache](../backend/app/services/scholarly/aggregator.py#L196) · [Visibility check](../backend/app/api/routes/discovery.py#L75)
